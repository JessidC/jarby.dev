The RAG story

SIESA's support chat ran on a third-party chatbot nobody could audit. I replaced it with an engine the company owns and can measure. It now answers about 1,000 conversations a day.

It started with the data

I pulled 90 days of production conversations, 55,350 chats and about 964K messages, and read what customers actually went through. There was no way to tell whether an answer was right. The model, the retrieval and the citations belonged to the vendor, so a no-invention policy couldn't be enforced from outside. And the worst moment came after the bot, when a customer asked for a person and the handoff stalled.

I took that to leadership as a business case with six decisions ranked by impact and cost. The main one was to build our own engine and fix the handoff in the same move.

The engine

  • No framework in the request path

    Python and FastAPI straight on the model API, so every millisecond and every token can be traced.

  • Claude on AWS Bedrock

    SIESA already ran on AWS, so billing and permissions stayed in the account it had. Sonnet answers, Haiku rewrites follow-ups and reads scanned pages.

  • Retrieve wide, rerank narrow

    pgvector search filtered by ERP module, then Cohere Rerank keeps the five passages the model reads.

  • Checked before it goes out

    Every citation has to exist in what was retrieved. A number that isn't in the sources sends the chat to a person.

  • Rules before the model

    About 170 deterministic rules handle greetings, risk and requests for a person before any LLM call.

  • Same contract as the old bot

    The support portal didn't change, so switching over and rolling back were both routine operations.

Shipping it, twice

  1. Jul 4 to 6Shadow run772 real conversations, answers hidden. A separate judge preferred the new engine 44% of the time, the old one 40%.
  2. Jul 9SwitchCustomers kept the same chat window.
  3. Jul 14RollbackBack to the vendor after a complaint from the support desk.
  4. Jul 16Switch againWith the root cause fixed.
  5. Today15 ERP modulesAbout 1,000 conversations a day. Reported to leadership and to the CEO.

Customer-service CSAT after redesigning the handoff to agents.

The fix was in the content

Hybrid retrieval looked like the obvious upgrade. I built it, measured it twice on real customer queries and switched it off. It recovered 0 of 5 failing cases, and every retrieval variant I tried landed within 3.6 points of the others.

So the effort went to the documents. I reprocessed 1,027 of them with multimodal OCR and set up a curation loop where agents approve about 150 new answers a week, from a console 44 agent accounts use.

Every change now ships the same way. A golden set per module scored by an LLM judge, an A/B replay on real traces and a significance test before and after. I rebuilt that method in the open as rag-eval-bench.

The platform belongs to SIESA. Figures come from project reports to leadership, July to October 2026. I can walk through the architecture in an interview.

Public code

rag-eval-bench

A bench that decides whether a RAG change ships. Golden set with questions the docs can't answer, an LLM judge, a validator that catches invented citations and numbers, and a paired McNemar test behind a CI gate. It runs on the public Odoo 18 docs.

What it found. Hybrid retrieval beat dense by 12.5 points, p = 0.02. A reranker added 1.4 points and pushed p95 latency from 2.5 s to 8.3 s, so it doesn't ship.
